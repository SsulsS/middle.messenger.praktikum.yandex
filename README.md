# Чат — Single Page Application

Учебный мессенджер на TypeScript (Яндекс Практикум, «Мидл фронтенд-разработчик»). Сейчас выполнен спринт 2: компонентная архитектура на базе `Block`, MVC, единая валидация форм, строгая типизация и линтеры.

- Развёрнутый проект: https://brilliant-lamington-df230c.netlify.app/

## Технологии

- TypeScript 6 (`strict`, `noImplicitAny`, `strictNullChecks`, `noUnusedLocals`, `noUnusedParameters`)
- Vite — сборка и dev-сервер
- Handlebars — шаблоны компонентов
- SCSS — стили
- ESLint, Stylelint, Prettier — качество и единый стиль кода
- Vitest + jsdom — тесты

На клиенте используется единственная библиотека — шаблонизатор Handlebars.

## Установка и запуск

Нужен Node.js 22.12 или новее.

```bash
npm install
npm run start
```

Приложение откроется на `http://localhost:3000`.

## Скрипты

| Команда            | Что делает                                             |
| ------------------ | ------------------------------------------------------ |

| `npm run dev`      | dev-сервер Vite на порту 3000                          |

## Страницы

| Адрес      | Страница                                   |
| ---------- | ------------------------------------------ |
| `/`        | список чатов и лента переписки             |
| `/login`   | вход                                       |
| `/sign-up` | регистрация                                |
| `/profile` | профиль: изменение данных, аватара, пароля |
| `/404`     | страница не найдена                        |
| `/500`     | ошибка сервера                             |

Страницы `/` и `/profile` доступны только после входа: гость попадает на `/login`. Неизвестный адрес ведёт на `/404`.

## Архитектура

Приложение построено по MVC.

- **View** — базовый класс `Block` (`src/core/Block.ts`), компоненты и страницы, которые от него наследуются. Разметка генерируется шаблонами Handlebars.
- **Model** — сервисы в `src/services`: `AuthService` хранит пользователя, `ChatService` — чаты и сообщения.
- **Controller** — `src/controllers`: связывают вьюшки с сервисами. Страницы не обращаются к сервисам напрямую.

`Block` реализует жизненный цикл `init → render → componentDidMount → componentDidUpdate`. Изменения props отслеживаются через `Proxy`; `setProps` вызывает одну перерисовку независимо от числа изменённых свойств. Дочерние блоки и массивы блоков передаются в props и подставляются в шаблон автоматически. Обработчики событий задаются в `props.events` и переживают перерисовку.

```
src/
  core/         Block, EventBus, renderBlock, кеш скомпилированных шаблонов
  router/       таблица маршрутов и переходы без перезагрузки страницы
  services/     модели: AuthService, ChatService
  controllers/  AuthController, ChatController
  components/   переиспользуемые компоненты: Button, Input, Form, Modal, AuthForm, ChatMessage
  pages/        страницы; блоки, нужные одной странице, лежат в её папке
  types/        типы предметной области
  constants/    маршруты, правила валидации
  utils/        функции без состояния, по одной на файл
```

Каждый компонент лежит в своей папке: `Name/Name.ts`, `Name.hbs`, при необходимости `Name.scss` и `Name.test.ts`. Тесты находятся рядом с тестируемым модулем.

## Формы и валидация

Все формы — вход, регистрация, профиль, смена пароля, отправка сообщения — построены на одном компоненте `Form`. Он проверяет поле при потере фокуса и всю форму при отправке, отменяет перезагрузку страницы и выводит собранные данные в `console.log`.

Правила проверки описаны один раз в `src/constants/validation.ts`:

| Поле                        | Правило                                                                     |
| --------------------------- | --------------------------------------------------------------------------- |
| `first_name`, `second_name` | латиница или кириллица, первая буква заглавная, без пробелов и цифр, дефис  |
| `login`                     | 3–20 символов, латиница, цифры, дефис и подчёркивание; не только цифры      |
| `email`                     | латиница, цифры и спецсимволы; обязательны `@` и точка, между ними буквы    |
| `password`                  | 8–40 символов, минимум одна заглавная буква и одна цифра                    |
| `phone`                     | 10–15 цифр, может начинаться с плюса                                        |
| `message`                   | не должно быть пустым                                                       |

## Стиль кода

- Prettier: одинарные кавычки, точки с запятой, ширина строки 80.
- Интерфейсы начинаются с `I`, типы — с `T`.
- Импорты идут от корня `src` (`components/Button/Button`) и сгруппированы: ядро, сервисы и контроллеры, утилиты и типы, компоненты, страницы, соседние файлы.
- Условия всегда оформляются с фигурными скобками.

## Ограничения текущего спринта

Сервера пока нет: вход, регистрация, профиль и чаты работают на клиенте, пользователь хранится в `localStorage`, сообщения — в памяти вкладки. Интеграция с HTTP API и WebSocket запланирована в спринтах 3–4.
